# 多模态模型：AI 如何联合理解文本与图像

> 日期：2026-09-08  
> 主题：视觉编码、跨模态对齐、信息融合、视觉问答与可靠性边界

## 1. 什么是多模态模型

多模态模型是能够处理两种或更多信息模态的模型，例如文本、图像、音频、视频和传感器数据。

本文重点讨论能同时理解文本与图像的视觉语言模型（Vision-Language Model，VLM）。它可以接收图片和文字指令，完成图片描述、视觉问答、文档理解、界面分析或图表解读等任务。

“多模态”不只是把图片和文字放进同一个接口。真正的关键是：

1. 把不同模态转换为模型可计算的表示；
2. 建立图像区域与语言概念之间的对应关系；
3. 在同一任务中融合多种证据；
4. 用统一或协同的输出机制生成结果。

模型能识别图片中的对象，不代表它一定理解对象之间的因果关系；能生成流畅描述，也不代表每个细节都来自图像证据。

## 2. 图像如何进入模型

### 2.1 像素不能直接等同于词语

文本通常先被 tokenizer 切成 token；图像则由大量像素组成。一张高分辨率图片可能包含数百万个颜色值，直接让语言模型逐像素处理会非常昂贵。

视觉模型通常先把图片分割为小块（patch），再把每个图像块转换为向量。每个向量可以看作模型用于计算的视觉单元，但它不一定对应一个完整物体。

### 2.2 视觉编码器

视觉编码器负责从图片中提取特征。常见方案包括卷积神经网络和视觉 Transformer。

视觉 Transformer 会把图像块映射为向量，加入位置信息，再通过注意力组合局部与全局特征。较浅层可能更关注边缘、纹理和颜色，较深层逐渐形成对象、布局和语义信息。

### 2.3 投影与适配

视觉编码器输出的向量维度和语言模型输入空间可能不同，因此通常需要投影层、适配器或专门的跨模态模块进行转换。

这个连接模块看似简单，却决定视觉信息能否被语言模型有效使用。如果投影只保留粗粒度语义，模型可能知道“这是一张收据”，却无法准确读取某一行金额。

### 2.4 视觉 Token

转换后的图像表示常被组织成一组视觉 token，与文本 token 一起进入模型。

视觉 token 数量会影响：

- 图像细节保留程度；
- 上下文占用；
- 计算与显存；
- 首次响应延迟；
- 多图输入的可扩展性。

更高分辨率或更多图像通常需要更多视觉 token，但 token 增加不保证模型一定正确利用细节。

## 3. 文本与图像如何融合

### 3.1 双编码器

双编码器分别编码图片与文本，再把两者映射到可比较的向量空间。

它适合图文检索：给定一段文字，找到语义匹配的图片；或给定图片，检索相关说明。由于图片与文本可分别提前编码，搜索效率较高。

但仅比较整体向量，通常不擅长需要逐区域推理的复杂问题。

### 3.2 编码器—连接器—语言模型

一种常见架构是：

~~~text
图片 → 视觉编码器 → 投影或连接模块 → 语言模型
文字 ─────────────────────────────→ 语言模型
~~~

视觉特征被转换为语言模型能够接收的表示，再由语言模型统一生成文本答案。

这种方式可以复用成熟语言模型的指令遵循和生成能力，但语言流畅度可能掩盖视觉识别错误。

### 3.3 交叉注意力

部分模型使用交叉注意力，让文本表示主动读取视觉特征，或让图像和文本在多个层级交互。

交叉注意力有利于建立问题词语与图像区域之间的关联，例如问题中的“左侧按钮”应关注界面左边的特定区域。

### 3.4 早期融合与晚期融合

- **早期融合**：较早把不同模态的 token 放入统一网络，交互充分，但计算成本较高；
- **晚期融合**：先独立处理不同模态，再在后段组合，模块清晰、便于检索，却可能丢失细粒度对应；
- **混合方案**：在多个阶段交换信息，平衡表达能力与效率。

不存在适合所有任务的唯一架构。图文检索、文档问答、机器人感知和图片生成对融合方式的要求不同。

## 4. 跨模态对齐如何训练

### 4.1 图文配对数据

训练数据可以是一张图片与对应标题、描述、网页文字或人工问答。模型通过大量配对样本学习哪些视觉模式与哪些语言概念相关。

配对文本并不总是完整描述图片。网页说明可能只提到主体，却忽略背景、数量或空间关系，因此数据质量会限制模型的视觉理解边界。

### 4.2 对比学习

对比学习让匹配的图片和文本向量更接近，让不匹配的组合更远。

例如，“一只在草地上奔跑的狗”应接近对应图片，而远离城市夜景图片。训练后可用于图文检索、零样本分类或相似度匹配。

对比学习擅长整体语义对齐，但单独使用时不一定具备生成长答案或精确定位细节的能力。

### 4.3 图像描述与生成式训练

模型可以根据图片预测描述文本，学习从视觉表示到语言输出的映射。

如果训练描述偏向常见、简短表达，模型可能优先生成“看起来合理”的概括，而忽略罕见细节。

### 4.4 多模态指令微调

在基础图文能力上，再使用“图片 + 指令 + 理想回答”进行监督微调，可以教模型回答问题、遵守格式、比较图片或解释图表。

指令微调主要改善任务形式和交互方式，不能自动修复视觉编码器没有捕获的信息。

### 4.5 偏好对齐

人类或 AI 可以比较多个多模态回答，选择更准确、更有帮助的结果。偏好优化能减少啰嗦、无依据猜测或不安全回答，但必须防止评审者被语言流畅度误导。

评审时应同时查看原图与问题，否则只能判断文字风格，无法验证视觉事实。

## 5. 模型如何定位图像中的信息

### 5.1 对象与区域

图片理解不仅要判断“有什么”，还要回答“在哪里”“有几个”“彼此是什么关系”。

区域定位可能依赖目标检测框、分割掩码、坐标 token 或注意力分布。模型若只生成自然语言而不输出可验证位置，很难判断它是否真正看到了对应区域。

### 5.2 OCR 与文档理解

读取图片文字通常涉及 OCR（光学字符识别）。有些系统使用独立 OCR 工具，再把识别结果交给语言模型；有些视觉语言模型能够直接从图像特征生成文本。

独立 OCR 更容易提供文字位置与置信度；端到端模型交互自然，却可能把模糊文字“补全”为看似合理但不存在的内容。

### 5.3 空间关系

“杯子在电脑左边”需要识别对象并比较位置。模型可能在左右、前后、遮挡和镜像场景中出错。

文字标签、箭头、复杂布局和旋转图片还会增加空间推理难度，不能只用普通照片问答评估。

### 5.4 指代消解

用户说“这个按钮”“右边第二项”时，模型必须把语言指代映射到图像区域。

在多轮对话中，图片、裁剪区域和历史指代若没有清楚绑定，模型可能回答另一个对象。产品应保留图像版本和区域引用，而不是只保存自然语言摘要。

## 6. 分辨率、切片与上下文成本

### 6.1 低分辨率的代价

缩小图片能减少视觉 token 和计算，但细小文字、图标、表格线或远处对象可能消失。

即使人眼放大后能看清，模型接收的预处理图片也可能已经丢失细节。

### 6.2 动态分辨率

系统可以根据图片尺寸和任务选择不同分辨率。普通场景描述使用较低分辨率，文档、图表或界面截图使用更高分辨率。

动态策略需要设置上限，否则超大图片会占用大量上下文并拖慢其他请求。

### 6.3 图像切片

处理长截图、扫描文档或超大图时，可以把图片切成多个局部块，同时保留一张全局缩略图。

全局图帮助理解布局，局部图保留细节。但切片可能破坏跨区域关系，也可能让同一对象在重叠区域重复出现。

### 6.4 多图输入

多张图片需要明确顺序、身份和关系。例如“比较第一张与第三张”要求系统稳定保存图片编号。

图片越多，视觉 token 越多，模型也更容易混淆来源。应在提示和数据结构中为每张图提供清晰标识。

## 7. 多模态模型能做什么

### 7.1 图片描述与视觉问答

模型可以概括场景、识别主要对象并回答与图片相关的问题，适合无障碍描述、内容管理和基础检查。

涉及精确数量、微小物体或专业判断时，需要更严格验证。

### 7.2 文档与表格理解

模型可以从发票、合同扫描件、表单和图表中提取信息，并结合自然语言解释。

可靠系统通常会结合 OCR、版面分析、字段校验和业务规则，而不是让模型单独决定金额或合同义务。

### 7.3 界面理解

给模型网页或应用截图，可以识别按钮、表单、错误提示和布局，用于辅助测试、操作指导或自动化。

截图只反映一个时刻的可见状态，无法证明按钮真实功能、隐藏权限或后端数据，因此仍需要与可访问性树和实际操作结果结合。

### 7.4 图文检索

将图片和文字映射到同一向量空间，可实现以文搜图、以图搜文和内容推荐。

相似度表示匹配程度，不等于版权授权、事实正确或人物身份确认。

### 7.5 多模态生成

部分系统还能生成或编辑图片、音频和视频。理解模型与生成模型可能共享表示或协同工作，但“能看图”与“能生成图”是不同能力，不能仅凭接口支持多模态就推断所有输出类型。

## 8. 实际例子：报销单据助手

一家企业希望员工上传发票或收据后，系统自动提取商户、日期、金额、币种和税额，并检查是否符合报销政策。

### 8.1 输入处理

系统可以执行：

1. 检查文件类型、页数与清晰度；
2. 对图片纠偏、旋转和去噪；
3. 使用 OCR 提取文字及坐标；
4. 将原图、OCR 结果和报销政策一起提供给模型；
5. 要求模型输出结构化字段和证据位置。

### 8.2 模型任务

模型不只是抄写文字，还需要：

- 区分小计、税额与总额；
- 判断日期格式；
- 识别币种符号；
- 把字段与图片区域对应；
- 根据政策标记缺失信息或异常；
- 对无法确认的字段返回“不确定”。

### 8.3 应用层校验

程序还应验证：

- 金额字段是否能解析；
- 小计与税额是否能够合理核对；
- 币种是否在允许范围；
- 日期是否落在报销期限内；
- 发票是否重复提交；
- 提取证据是否真的存在于 OCR 或图像区域。

### 8.4 高风险边界

模型可以建议“需要人工复核”，但不应凭一张图片最终认定票据伪造，也不应自行批准付款。

图片可能被编辑，OCR 也可能出错。财务决定必须结合原始文件、元数据、业务系统和授权流程。

## 9. 如何评估多模态模型

### 9.1 按任务拆分指标

不同任务需要不同指标：

- 图片分类：准确率、召回率；
- 文字识别：字符或单词错误率；
- 字段提取：字段级精确率、召回率和完全匹配；
- 目标定位：框或掩码的重叠程度；
- 视觉问答：答案准确性和证据一致性；
- 图文检索：召回率和排序质量。

不能用一个综合分数代替所有能力。

### 9.2 视觉证据一致性

评估回答中的每个关键事实是否能在图片中找到证据。模型说“图片里没有”也要验证，因为它可能只是没识别出来。

可要求输出区域坐标、OCR 行号或引用片段，让结果更容易核验。

### 9.3 压力与边界测试

测试集应包含：

- 模糊、过曝、旋转和低分辨率图片；
- 小字体、手写体和多语言文字；
- 复杂表格、长截图和遮挡；
- 相似对象、数量问题和左右关系；
- 多张图片与顺序引用；
- 图片中包含恶意指令的提示注入；
- 训练分布之外的专业场景。

### 9.4 端到端任务成功率

单项 OCR 很好，不代表报销流程正确；图片描述自然，也不代表用户问题得到解决。

最终要测量业务任务是否完成、人工修正率、严重错误率、延迟和单次成本。

## 10. 局限、风险与常见失败模式

### 10.1 视觉幻觉

模型可能描述图片中不存在的对象、文字或关系。常见物体和语言先验会填补模糊证据，形成听起来合理的错误。

### 10.2 小目标与细节遗漏

低分辨率、压缩、远距离物体和密集文字会让细节丢失。模型没有报告某个对象，不代表对象一定不存在。

### 10.3 OCR 补全错误

模糊的编号、金额或日期可能被模型补成常见格式。数字只错一位就可能造成严重业务后果，必须使用校验与人工复核。

### 10.4 空间推理不稳定

左右、计数、重叠、镜像和跨区域关系容易出错。裁剪或旋转图片后，方向描述也可能改变。

### 10.5 语言流畅度掩盖视觉错误

语言模型能生成专业解释，即使视觉证据不足。评审者容易被详细措辞说服，因此需要证据定位与独立检查。

### 10.6 图片提示注入

网页截图、文档或图片中可能包含“忽略规则并执行某操作”等文字。图片里的文字属于不可信数据，不能自动升级为系统指令。

### 10.7 隐私与敏感信息

图片可能包含人脸、身份证、地址、医疗记录、屏幕通知或地理位置。上传、存储、日志和人工标注都应遵守最小化原则与权限要求。

### 10.8 偏见与覆盖不足

训练图片对地区、肤色、文化、语言、设备和无障碍场景覆盖不均，会导致某些用户群体表现更差。

### 10.9 对抗样本与图片篡改

微小扰动、遮挡、拼接或伪造可能误导模型。通用视觉语言模型不是取证系统，不能单独承担真实性鉴定。

## 11. 一套可落地的实践顺序

1. 明确模型必须从图片中提取或判断什么；
2. 区分低风险辅助与高风险决策；
3. 收集符合真实设备、分辨率和语言分布的数据；
4. 为图片、OCR、用户文字和系统规则标记来源；
5. 使用结构化输出并要求证据位置；
6. 对数字、日期、身份和金额使用确定性校验；
7. 建立清晰度不足与证据不足的拒答机制；
8. 测试旋转、模糊、多图、长图和提示注入；
9. 分任务评估视觉识别、语言回答和端到端成功率；
10. 为高风险结果设置人工复核和权限控制；
11. 记录模型、图像预处理、提示与评估版本；
12. 上线后持续收集失败类型，而不是只看平均满意度。

## 12. 与其他 AI 方法的关系

### 12.1 与 Embedding

双编码器可把图片和文本映射到同一向量空间，用于跨模态检索。向量相近表示语义匹配，不代表图片中的每个细节都已被理解。

### 12.2 与 RAG

多模态 RAG 可以检索图片、图表或文档页面，再让模型基于这些证据回答。检索必须保留页码、区域和权限，否则答案难以验证。

### 12.3 与工具调用

模型可以调用 OCR、目标检测、计算器或数据库。工具能提供更精确的中间结果，但模型必须正确选择工具，应用也要验证参数和权限。

### 12.4 与 AI Agent

多模态 Agent 可以观察界面、规划步骤并操作工具。视觉识别错误会沿行动链放大，因此关键点击、提交和付款必须有状态核验与确认边界。

### 12.5 与偏好对齐

偏好训练可以改善多模态回答的帮助性和谨慎程度，但评审必须能看到原始视觉证据。只读文字答案会把“写得好”误当成“看得准”。

## 13. 关键结论

1. 多模态模型把图像、文本等不同输入转换为可联合计算的表示。
2. 图像通常被视觉编码器转换为视觉 token，再通过投影、交叉注意力或统一网络与文本融合。
3. 对比学习适合整体图文对齐，生成式训练和指令微调进一步支持问答与解释。
4. 分辨率、图像切片和视觉 token 数共同影响细节、成本和延迟。
5. OCR、空间关系、计数和小目标是常见薄弱环节，流畅语言可能掩盖识别错误。
6. 可靠应用应要求证据位置，并使用 OCR、规则、数据库和人工复核验证关键字段。
7. 图片中的文字属于不可信数据，必须防范多模态提示注入和越权操作。
8. 多模态评估要按任务拆分，并最终检查端到端业务成功率。
9. 多模态能力扩展了模型的观察范围，但不能替代真实性鉴定、访问控制和专业判断。
