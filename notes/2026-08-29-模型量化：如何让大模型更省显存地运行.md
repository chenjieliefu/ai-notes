# 模型量化：如何让大模型更省显存地运行

> 日期：2026-08-29  
> 主题：低精度表示、校准、推理性能与质量权衡

## 1. 什么是模型量化

模型量化（Quantization）是用更低位数的数据表示模型权重、激活值或缓存，从而减少存储、显存占用和计算成本的技术。

模型训练和推理常使用 FP32、FP16 或 BF16 等浮点格式。量化可以把部分数据转换为 INT8、INT4 等低精度整数，或者其他低位浮点格式。

它解决的核心问题是：能否用更少的比特近似原始数值，同时把模型质量损失控制在可接受范围内。

量化不是简单地压缩文件。它会改变推理时的数值表示和计算路径，因此效果同时取决于模型、量化方法、硬件和推理引擎。

## 2. 为什么量化能节省资源

### 2.1 权重存储变小

假设一个模型有 70 亿个参数，只计算权重的理论大小：

- FP32：每个参数 4 字节，约 28 GB；
- FP16/BF16：每个参数 2 字节，约 14 GB；
- INT8：每个参数 1 字节，约 7 GB；
- INT4：每个参数 0.5 字节，约 3.5 GB。

实际运行还需要量化比例、元数据、临时张量、激活值、KV Cache 和框架开销，所以显存需求不会刚好等于理论权重大小。

### 2.2 内存带宽压力降低

大模型推理常需要频繁从显存读取权重。低位权重体积更小，在支持相应计算的硬件上，可以减少数据搬运并提高吞吐。

### 2.3 更容易部署

量化后，原本只能运行在服务器 GPU 上的模型，可能可以部署到较小显卡、CPU、手机或边缘设备。但“能装下”不等于“运行快”，还要看算子与硬件支持。

## 3. 量化的基本原理

### 3.1 从连续值映射到离散整数

一个常见的线性量化过程可以概括为：

1. 选择浮点数的表示范围；
2. 计算缩放系数 scale；
3. 必要时设置零点 zero point；
4. 将浮点值除以 scale 后取整；
5. 把结果截断到整数格式允许的范围。

概念公式为：

q = clamp(round(x / scale) + zero_point)

推理时可以近似还原：

x ≈ scale × (q - zero_point)

取整和截断会引入量化误差。位数越低，可用离散值越少，近似误差通常越大。

### 3.2 对称量化与非对称量化

对称量化让数值范围围绕零点对称，计算简单，适合正负分布接近的张量。

非对称量化允许零点偏移，更适合范围明显偏向一侧的数据，但实现会更复杂。

### 3.3 粒度决定精度和开销

常见粒度包括：

- Per-tensor：整个张量共享一组量化参数；
- Per-channel：每个输出通道使用独立参数；
- Per-group：把权重分组，每组使用独立参数。

粒度越细，通常越能适应不同分布并提高精度，但需要更多元数据，也可能增加实现复杂度。

## 4. 哪些数据可以被量化

### 4.1 权重量化

只把模型权重变为低精度，激活值仍使用浮点计算。权重量化实现相对直接，是大模型部署中常见的做法。

### 4.2 权重与激活量化

同时量化权重和中间激活值，可以进一步降低带宽和计算成本，但激活分布会随输入变化，通常比权重量化更难保持质量。

### 4.3 KV Cache 量化

自回归生成会缓存注意力中的 Key 和 Value。上下文越长、并发越高，KV Cache 占用越明显。对它进行量化可以减少长上下文服务的显存，但可能影响注意力精度，需要单独评估。

### 4.4 选择性保留高精度

并非所有层都同样敏感。实践中常保留部分归一化、输出层或异常敏感模块的高精度，只量化主要矩阵乘法。这是一种质量与资源之间的折中。

## 5. 训练后量化与量化感知训练

### 5.1 训练后量化

训练后量化（Post-Training Quantization，PTQ）直接对已经训练好的模型进行量化，不重新完整训练。

它部署快、成本低，常需要一小组校准数据估计权重或激活的分布。GPTQ、AWQ 等方法属于面向大模型权重量化的不同技术路线，它们会以不同方式减少低位表示带来的误差。

### 5.2 量化感知训练

量化感知训练（Quantization-Aware Training，QAT）在训练或微调过程中模拟量化误差，让模型逐步适应低精度表示。

QAT 通常能在更低位数下保持更好质量，但需要训练数据、算力和更复杂的流程。它适合对质量敏感、部署规模大且值得投入优化的场景。

### 5.3 如何选择

先用 PTQ 建立基线。如果资源收益明显、质量满足要求，就没有必要增加训练复杂度。只有当 PTQ 的质量损失不可接受，且低位部署价值足够高时，再考虑 QAT 或更精细的方法。

## 6. 校准数据为什么重要

### 6.1 估计真实分布

校准数据用于观察模型在代表性输入下的权重或激活范围。若校准样本只包含短英文，模型上线处理长中文、代码或专业文本时，分布可能不同，量化误差会扩大。

### 6.2 处理离群值

少量极大或极小的离群值会拉宽量化范围，使大多数普通数值只能使用较少离散级别。常见策略包括裁剪范围、按通道量化、重排缩放或对敏感部分保留更高精度。

### 6.3 避免数据泄漏

校准数据不应与最终测试集重合。否则量化方案可能过度适应该批样本，评估结果会偏高。

校准数据通常不需要和训练数据一样庞大，但必须覆盖真实任务类型和输入长度。

## 7. 实际例子：把 7B 模型部署到单张显卡

一个团队希望在内部服务器上运行约 70 亿参数的客服模型，显卡可用显存有限。

### 7.1 建立未量化基线

团队先使用 FP16 模型，记录：

- 任务正确率；
- 首 token 延迟；
- 每秒生成 token 数；
- 峰值显存；
- 不同上下文长度下的并发能力；
- 严重安全失败率。

如果没有基线，就无法判断量化到底带来了什么。

### 7.2 尝试 INT8 与 INT4 权重量化

INT8 通常提供较温和的压缩；INT4 进一步缩小权重，但质量风险更高。团队分别使用代表性中文客服、订单号、政策问答和长对话做校准与测试。

### 7.3 观察真实瓶颈

INT4 权重理论上约为 FP16 的四分之一，但运行时仍有量化参数、KV Cache 和临时内存。若长上下文下 KV Cache 才是主要瓶颈，只压缩权重不会按预期提高并发。

### 7.4 做上线决策

如果 INT4 在普通问答上几乎不退化，却让关键订单号复制错误增加，就不能只看平均分。团队可以：

1. 改用 INT8；
2. 对敏感层保留高精度；
3. 用工具校验订单号；
4. 在高风险任务中切换更高精度模型。

合理方案不是追求最低位数，而是满足质量门槛后获得最大的资源收益。

## 8. 量化与推理速度的关系

### 8.1 更小不一定更快

如果硬件没有高效的低位算子，推理引擎可能需要先反量化，再用浮点计算，额外开销会抵消带宽收益。

### 8.2 批大小会改变结果

低并发时，框架调度和解码开销可能占主导；高并发时，显存带宽和 KV Cache 更关键。必须在目标批大小和上下文长度下测量。

### 8.3 预填充与解码阶段不同

输入上下文的预填充阶段通常进行大量并行计算；逐 token 解码阶段更容易受权重读取和内存带宽影响。量化对两个阶段的加速效果可能不同。

### 8.4 端到端性能才有意义

真正需要观察的是用户请求的延迟、吞吐、并发和成本，而不是某个矩阵乘法的理论速度。

## 9. 如何评估量化模型

### 9.1 质量评估

应比较原始模型与量化模型在相同数据、提示和解码参数下的表现，包括：

- 任务完成率；
- 事实与推理正确性；
- 格式遵循率；
- 长文本稳定性；
- 多语言与代码能力；
- 安全与拒绝行为。

困惑度等通用指标可以辅助观察变化，但不能替代真实任务评估。

### 9.2 性能评估

至少记录：

- 模型文件和权重大小；
- 加载后的峰值内存或显存；
- 首 token 延迟；
- 每秒生成 token 数；
- 不同并发下的吞吐；
- 不同上下文长度下的 KV Cache 占用；
- 单位成功任务的成本与能耗。

### 9.3 分场景设门槛

平均质量下降很小，不代表所有场景都安全。数字、代码、专有名词和少数语言可能更敏感，应按任务和风险等级切分指标。

## 10. 局限、风险与常见失败模式

### 10.1 只看模型文件大小

磁盘文件变小不代表运行时显存按同比例下降。激活值、KV Cache、运行库和临时缓冲区都要计入。

### 10.2 假设位数越低越好

更低位数带来更高压缩，也可能导致更大质量损失。最终目标是满足业务门槛，而不是赢得“最小模型”比赛。

### 10.3 校准分布不匹配

用短英文校准，却部署到长中文和代码任务，会低估量化风险。校准集必须接近真实流量。

### 10.4 忽略离群值和敏感层

统一量化所有层可能让少数关键模块严重退化。需要检查逐层敏感度，并考虑混合精度。

### 10.5 硬件或算子不支持

某个格式在一类 GPU 上很快，在 CPU、手机芯片或另一类 GPU 上可能没有高效实现。模型格式、推理引擎和目标硬件必须一起验证。

### 10.6 只测短文本

短基准看不出 KV Cache 与长上下文误差。应覆盖实际输入长度和生成长度。

### 10.7 忽略安全回归

量化可能改变低概率 token 的排序，使拒绝行为、敏感信息处理或工具调用发生变化。量化后必须重新运行安全评估。

### 10.8 格式可加载但结果错误

量化模型能成功加载，不代表权重排列、分组参数和 tokenizer 完全匹配。需要用固定输入对照输出，并记录转换工具和版本。

## 11. 一套可落地的优化顺序

1. 明确目标硬件、并发、上下文和质量门槛；
2. 建立高精度模型的质量与性能基线；
3. 先尝试成熟的训练后权重量化；
4. 使用代表性校准集和独立测试集；
5. 同时测量质量、显存、延迟、吞吐和成本；
6. 检查数字、代码、多语言与长上下文等敏感场景；
7. 根据结果调整位数、分组大小与混合精度；
8. 确认推理引擎真正使用目标低位算子；
9. 小流量上线并保留高精度回退方案；
10. 模型、量化工具或硬件升级后重新评估。

## 12. 关键结论

1. 模型量化用低精度数值近似权重、激活或缓存，以减少资源占用。
2. 位数越低，理论压缩越大，但量化误差和工程风险通常也越高。
3. 粒度、缩放、零点、离群值处理和校准数据共同决定质量。
4. PTQ 成本低、适合先建立基线；QAT 成本更高，但可让模型适应量化误差。
5. 权重大小只是显存的一部分，长上下文下还要关注 KV Cache。
6. 低位模型能否加速取决于目标硬件、推理引擎和算子支持。
7. 最优方案是在真实质量门槛内取得显存、速度与成本的整体收益。
