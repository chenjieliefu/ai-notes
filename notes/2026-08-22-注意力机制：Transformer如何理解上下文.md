# 注意力机制：Transformer 如何理解上下文

> 日期：2026-08-22  
> 主题：自注意力、上下文表示与 Transformer 的核心工作原理

## 1. 为什么需要注意力机制

自然语言中的含义依赖上下文。同一个词放在不同句子里，可能表达完全不同的意思；一个代词指向谁，也常常需要结合前后内容判断。

例如：

~~~text
小李把报告交给小王，因为他明天要出差。
~~~

这里的“他”可能指小李，也可能指小王。模型不能只看“他”这个字，而要综合句子中的人物、动作和因果关系。

在注意力机制出现之前，序列模型常按顺序处理文本。随着句子变长，早期信息需要经过许多计算步骤才能影响后面的词，容易出现信息衰减，也难以高效并行训练。

注意力机制提供了另一种思路：

> 处理当前位置时，直接计算它与上下文中其他位置的相关程度，再按相关程度汇总信息。

这样，模型能够动态决定“当前应该关注哪里”。

## 2. 注意力的核心直觉

可以把注意力想象成一次带权重的信息检索。

当我们阅读句子：

~~~text
银行把贷款申请退回了，因为材料不完整。
~~~

理解“退回”的原因时，“材料不完整”比“银行”更关键。模型会为上下文中的不同词分配不同权重，并把它们的信息组合起来。

注意力计算通常包含三个角色：

- **Query（查询）**：当前位置正在寻找什么信息；
- **Key（键）**：每个位置用什么特征供查询匹配；
- **Value（值）**：匹配后真正被汇总的信息。

它们可以类比为搜索系统：

~~~text
Query：用户输入的搜索问题
Key：文档的索引特征
Value：文档中的实际内容
~~~

模型先比较 Query 与各个 Key 的匹配程度，再使用匹配权重加权汇总对应的 Value。

## 3. 从输入到 Q、K、V

假设输入句子经过分词和 Embedding 后，得到一组向量：

~~~text
X = [x₁, x₂, x₃, ..., xₙ]
~~~

模型通过三组可训练的线性变换生成 Q、K、V：

~~~text
Q = XW_Q
K = XW_K
V = XW_V
~~~

其中，W_Q、W_K、W_V 是训练过程中学到的参数。

这三个向量并不是词的固定属性。同一个输入向量经过不同变换后，分别承担“发起查询”“被匹配”和“提供内容”的角色。

模型训练的过程，就是不断调整这些变换矩阵，使注意力权重更有利于完成预测任务。

## 4. 缩放点积注意力

Transformer 中常用的注意力形式是缩放点积注意力：

~~~text
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V
~~~

这条公式可以拆成四步理解。

### 4.1 计算匹配分数

Q 与 K 做点积：

~~~text
scores = QKᵀ
~~~

点积越大，通常表示查询与某个位置越匹配。

如果序列中有 n 个 token，就会得到一个 n × n 的分数矩阵。矩阵中的每个元素表示“某个 token 对另一个 token 的关注程度”。

### 4.2 缩放分数

分数除以 √dₖ，其中 dₖ 是 Key 的维度。

维度较大时，点积数值容易变得很大，使 Softmax 输出过于极端，梯度也可能变得不稳定。缩放能够让训练更平稳。

### 4.3 使用 Softmax 归一化

Softmax 把一组分数转换为权重：

~~~text
[2.1, 0.5, -0.3] → [0.76, 0.15, 0.09]
~~~

同一查询对应的权重之和为 1。模型因此能够判断应该从哪些位置获取更多信息。

### 4.4 加权汇总 Value

最后，用注意力权重对 Value 做加权求和。得到的新向量不再只代表当前 token 本身，而是融合了与它相关的上下文信息。

## 5. 自注意力为什么叫“自”注意力

在自注意力（Self-Attention）中，Q、K、V 都来自同一个输入序列。

例如，处理句子：

~~~text
猫趴在窗台上，它正在晒太阳。
~~~

当模型处理“它”时，可以关注“猫”；处理“晒太阳”时，可以同时关注“猫”和“窗台”。

每个 token 都会与序列中的其他 token 建立联系，所以输出是“上下文化表示”：

- 输入 Embedding 主要表示 token 的初始含义；
- 自注意力输出表示 token 在当前句子里的含义。

这也是 Transformer 能够处理指代、修饰关系和长距离依赖的重要原因。

## 6. 一个简化的计算例子

假设句子只有三个 token：

~~~text
机器 / 学习 / 有趣
~~~

处理“学习”时，模型计算出它对三个位置的注意力权重：

~~~text
机器：0.35
学习：0.45
有趣：0.20
~~~

新的“学习”向量可以简化表示为：

~~~text
0.35 × V_机器 + 0.45 × V_学习 + 0.20 × V_有趣
~~~

这个向量同时吸收了“机器”和“有趣”的信息，因此更接近“机器学习这一主题很有趣”的语境，而不只是孤立的“学习”。

真实模型中的向量维度、层数和计算过程更复杂，但核心思想相同：根据相关性动态组合上下文。

## 7. 多头注意力

单组注意力可能只擅长捕捉某一类关系。Transformer 使用多头注意力（Multi-Head Attention），让模型在多个表示空间中并行学习。

不同注意力头可能倾向于关注：

- 主语与谓语关系；
- 代词与指代对象；
- 形容词与被修饰词；
- 因果关系；
- 时间和位置关系；
- 相隔较远但语义相关的内容。

多头注意力可以写成：

~~~text
headᵢ = Attention(QWᵢ_Q, KWᵢ_K, VWᵢ_V)
MultiHead = Concat(head₁, ..., headₕ)W_O
~~~

各个头的输出被拼接，再经过一次线性变换形成最终结果。

需要注意的是，人们可以观察某些头呈现出的模式，但不能简单断言“第几个头永远负责某种语法关系”。模型内部表示通常是分布式的，同一能力可能由多个组件共同承担。

## 8. 位置信息从哪里来

自注意力本身更关注 token 之间的关系，不天然知道顺序。

下面两句话包含相同词语，但意思不同：

~~~text
狗追猫。
猫追狗。
~~~

如果没有位置信息，模型很难区分谁追谁。因此 Transformer 必须把位置编码加入输入。

常见做法包括：

- 固定的正弦、余弦位置编码；
- 可学习的位置向量；
- 相对位置表示；
- 旋转位置编码等方法。

不同方案的共同目标，是让模型知道 token 的顺序和相对距离。

位置表示会影响模型处理长文本的能力。模型在训练时见过的长度、采用的位置方法以及推理时的上下文长度，都会影响远距离信息的利用效果。

## 9. 为什么语言模型需要因果遮罩

生成式语言模型按顺序预测下一个 token。训练时，模型不能偷看当前位置之后的正确答案。

例如：

~~~text
人工智能正在改变 ___
~~~

预测空白处时，只能使用左侧上下文，不能提前看到后面的词。

因果遮罩（Causal Mask）会把未来位置的注意力分数屏蔽掉：

~~~text
位置 1：只能看位置 1
位置 2：可以看位置 1～2
位置 3：可以看位置 1～3
~~~

被屏蔽的位置在 Softmax 后得到接近 0 的权重，从而保证自回归训练与实际生成过程一致。

除此之外，系统还可能使用 Padding Mask，忽略为了对齐批次长度而补充的空白 token。

## 10. Transformer 层不只有注意力

注意力是 Transformer 的核心组件，但完整的 Transformer 层还包括其他结构。

一个简化流程是：

~~~text
输入
 ↓
多头自注意力
 ↓
残差连接与归一化
 ↓
前馈神经网络
 ↓
残差连接与归一化
 ↓
输出
~~~

### 10.1 前馈神经网络

前馈网络对每个位置分别进行非线性变换。注意力负责在不同 token 之间交换信息，前馈网络则进一步处理每个位置获得的信息。

### 10.2 残差连接

残差连接把模块输入直接加到输出上，有助于深层网络保留信息并稳定训练。

### 10.3 归一化

归一化控制激活值的分布，使训练过程更稳定。不同 Transformer 架构可能把归一化放在子层之前或之后。

堆叠多层后，模型可以逐步形成从局部词法到复杂语义的表示。

## 11. 编码器注意力与解码器注意力

Transformer 最初常被描述为编码器—解码器结构。

### 11.1 编码器自注意力

编码器通常允许每个位置查看整个输入序列，适合理解、分类和信息抽取。

### 11.2 解码器自注意力

解码器使用因果遮罩，只能关注当前位置及之前的 token，适合自回归生成。

### 11.3 交叉注意力

在翻译等编码器—解码器任务中，解码器还会通过交叉注意力读取编码器输出：

- Query 来自解码器；
- Key 和 Value 来自编码器。

这样，生成目标语言的每个词时，模型可以动态关注源语言中相关的部分。

许多现代大语言模型采用仅解码器架构，但自注意力、因果遮罩和堆叠层的核心思想仍然适用。

## 12. 注意力带来的优势

### 12.1 更容易建立长距离关系

两个 token 即使相距很远，也可以在一次注意力计算中直接交互，不必逐步传递信息。

### 12.2 训练可以高度并行

训练阶段可以同时处理一个序列中的多个位置，更适合现代计算硬件。

### 12.3 表示会随上下文变化

同一个 token 在不同句子中可以得到不同表示，使模型更好地处理多义词和指代关系。

### 12.4 能够统一多种模态

注意力不只适用于文本。图像块、音频帧和其他序列化数据也可以转换成向量，再使用类似机制建模关系。

## 13. 局限与常见误区

### 13.1 计算量随序列长度快速增长

标准自注意力需要构建 n × n 的关系矩阵。序列长度翻倍时，相关计算和显存需求通常会显著增加。

这也是长上下文模型成本较高的原因之一。稀疏注意力、滑动窗口、分块处理和高效注意力实现，都是常见优化方向。

### 13.2 有长上下文不等于能充分利用

模型能够接收很长的文本，不代表它会稳定使用其中每一条信息。重要内容的位置、干扰信息、任务难度和训练方式都会影响效果。

因此，实际应用仍需要：

- 只提供相关上下文；
- 清晰组织关键信息；
- 对长文本任务进行专项评估；
- 必要时结合检索和分层总结。

### 13.3 注意力权重不等于完整解释

某个 token 获得较高注意力权重，只能说明特定层、特定头中的信息流动较强，不能直接证明模型做出最终结论的全部原因。

模型预测还受到其他注意力头、前馈网络、残差连接和多层组合的影响。把注意力图当作完整可解释性证据，容易得出过度结论。

### 13.4 模型仍可能关注错误线索

注意力机制能学习关系，但不会自动保证关系真实、合理或无偏见。如果训练数据包含虚假相关性，模型也可能依赖错误特征。

### 13.5 提示注入会利用上下文机制

语言模型会把上下文中的文本纳入计算。恶意内容可能伪装成指令，诱导模型忽略原始规则。

应用需要区分系统指令、用户输入和外部检索资料，并限制工具权限，不能仅依靠模型自行判断可信度。

## 14. 实际应用中的设计启示

### 14.1 把关键信息写清楚

模型通过上下文建立关系。明确的标题、结构、约束和输出格式，通常比含糊指令更容易被正确利用。

### 14.2 控制无关上下文

更多内容不一定更好。无关资料会竞争注意力，增加成本并可能降低准确性。

### 14.3 为长文本建立评估集

应测试关键信息位于开头、中间和结尾时的表现，并加入相似干扰项，观察模型是否真正找到依据。

### 14.4 结合检索系统

对大型知识库，不应把所有文档一次性塞入上下文。先通过搜索或向量检索筛选相关内容，再交给模型处理，通常更有效。

## 15. 关键结论

- 注意力机制让模型根据当前任务动态选择并组合上下文信息。
- Query、Key、Value 分别承担查询、匹配和内容汇总的角色。
- 自注意力使每个 token 获得与当前句子相关的上下文化表示。
- 多头注意力允许模型从多个表示空间同时学习关系。
- 位置表示负责补充顺序信息，因果遮罩防止生成模型看到未来答案。
- 完整 Transformer 层还包含前馈网络、残差连接和归一化。
- 标准注意力的计算成本会随序列长度快速增加。
- 更长的上下文窗口不等于模型一定能可靠利用全部信息。
- 注意力权重可以帮助观察模型内部行为，但不是完整的因果解释。
- 实际应用应控制上下文质量，并通过真实任务评估长文本能力。
